# State illustrations and image prompts

When a screen carries a visual alongside its UI — an empty state, an error, a success moment, a welcome, a hero, or an illustration slot — the visual is half the answer. This reference gives two routes for that visual, and the rules for choosing between them.

## How this fits the mode system

- **Baseline mode.** Reach for the ready-made SVGs in `assets/` and recolour them with DaisyUI semantic tokens via `currentColor`. No custom art.
- **Design mode.** Build a small on-brand SVG that follows the rules below, or generate a single illustration from a JSON prompt that respects the theme palette.
- **Advanced mode.** Use the JSON prompt for a richer, art-directed hero or campaign image. Confirm contrast against both themes before shipping.

When unsure, default to Baseline.

## Route A: inline SVG

Use inline SVG when the graphic is:

- A simple state illustration (empty inbox, no results, success check, error triangle).
- An icon or pictogram.
- Monochrome or two-tone.
- Under 4 KB, ideally under 1 KB.

The SVG ships as code. The surrounding text colour drives the fill via `currentColor`, so DaisyUI semantic tokens (`text-primary`, `text-base-content`, `text-error`) recolour the SVG automatically across themes. No second file for dark mode.

### Rules for the SVG

1. Use a square `viewBox` (commonly `0 0 24 24` for icons, `0 0 240 180` for state illustrations).
2. Set `fill="currentColor"` or `stroke="currentColor"` so the SVG inherits the surrounding text colour. Use a second colour only when the design needs depth.
3. Use `stroke-linecap="round"` and `stroke-linejoin="round"` for friendly geometry.
4. Skip filters, gradients, and embedded fonts. They balloon the file and break theming.
5. Include `role="img"` and an `<title>` so the SVG is accessible.

### Ready-to-use templates

The `assets/` directory ships with four starter SVGs. Adapt them as needed.

- `assets/empty-state.svg`: an open box with a soft shadow. Use for empty inboxes, empty lists, and first-run views.
- `assets/error-state.svg`: a circle with a slash, balanced and calm. Use for non-fatal errors.
- `assets/success-state.svg`: a check inside a circle. Use for completion moments.
- `assets/welcome-state.svg`: a stylised wave. Use for first-run welcomes.

### A worked inline example

For an *No invoices yet* empty state, the SVG might be:

```svg
<svg role="img" aria-labelledby="title-empty-invoices" viewBox="0 0 240 180" xmlns="http://www.w3.org/2000/svg" width="240" height="180">
  <title id="title-empty-invoices">Empty invoices tray</title>
  <g fill="none" stroke="currentColor" stroke-width="2" stroke-linecap="round" stroke-linejoin="round">
    <rect x="48" y="56" width="144" height="96" rx="8" />
    <path d="M48 96 L96 96 L108 112 L132 112 L144 96 L192 96" />
    <line x1="84" y1="40" x2="84" y2="56" />
    <line x1="120" y1="32" x2="120" y2="56" />
    <line x1="156" y1="40" x2="156" y2="56" />
  </g>
</svg>
```

Drop it inside a `text-primary` parent (or any semantic token) and the stroke recolours to match the theme. The visual and the copy work as one unit:

```astro
<div class="flex flex-col items-center text-base-content/70">
  <div class="mb-4 text-primary">
    <!-- inline SVG goes here -->
  </div>
  <h3 class="text-xl font-semibold text-base-content">No invoices in May.</h3>
  <p class="mt-1">Send your first one to see it here.</p>
</div>
```

## Route B: JSON image-prompt

Use a JSON image-prompt when the graphic is:

- A richer illustration, photograph, or hero image.
- A scene with multiple subjects, lighting, or atmosphere.
- Going to be generated by a text-to-image model (Imagen, Midjourney, DALL-E, Stable Diffusion).
- Going to be handed off to a designer for art direction.

Structured prompts beat freeform prompts. They lock the variables the brand cares about (palette, style, framing) and leave the variables that matter to the surface (subject, mood) flexible.

### The schema

```json
{
  "purpose": "What the image is for, in one line.",
  "surface": "Where the image lives (hero, modal, empty state, social post, blog header).",
  "subject": "The primary subject in plain language.",
  "scene": "Optional. The setting or environment.",
  "style": {
    "medium": "vector illustration | 3D render | photograph | line art | flat illustration | watercolour | isometric",
    "mood": "Three adjectives at most.",
    "lighting": "Optional. Soft daylight, dramatic backlight, neutral studio, etc.",
    "framing": "wide | medium | close | overhead | low angle"
  },
  "palette": {
    "primary": "#hex or named brand colour",
    "secondary": "#hex or named brand colour",
    "accent": "#hex or named brand colour",
    "background": "#hex or named brand colour"
  },
  "composition": {
    "aspect_ratio": "1:1 | 16:9 | 4:3 | 3:4 | 9:16",
    "negative_space": "left | right | top | bottom | centre",
    "focal_point": "Where the eye should land first."
  },
  "include": [
    "Specific elements the image must contain."
  ],
  "exclude": [
    "Elements to keep out (text, logos, photoreal faces, watermarks)."
  ],
  "accessibility": {
    "alt_text": "The alt text the image will ship with.",
    "contrast_target": "WCAG AA on the surface where it sits."
  },
  "notes": "Anything the designer or model should know that does not fit above."
}
```

Pull the palette from the DaisyUI theme tokens defined in `global.css` (export the OKLCH values to hex if the model needs hex). That way the generated image lands on-brand against both light and dark surfaces without a second pass.

### A worked example

A landing page hero for a finance product, paired with the heading *Close books in 3 days instead of 30*.

```json
{
  "purpose": "Hero illustration for a finance close-cycle landing page.",
  "surface": "Hero block, top of fold, paired with primary CTA 'Start free trial'.",
  "subject": "A calm finance lead reviewing a clean dashboard on a laptop, with three small stacks of paper neatly placed to the side.",
  "scene": "A modern, daylit home office with one houseplant and a coffee mug.",
  "style": {
    "medium": "flat illustration",
    "mood": "calm, confident, focused",
    "lighting": "soft daylight from the left",
    "framing": "medium"
  },
  "palette": {
    "primary": "#0E1E40",
    "secondary": "#E8F0FF",
    "accent": "#5B8DEF",
    "background": "#F7F8FB"
  },
  "composition": {
    "aspect_ratio": "16:9",
    "negative_space": "right",
    "focal_point": "The laptop screen, glowing softly."
  },
  "include": [
    "A laptop with a stylised dashboard chart.",
    "Three small neat stacks of paper.",
    "One coffee mug and one houseplant."
  ],
  "exclude": [
    "Photoreal faces, brand logos, text inside the image, watermarks, currency symbols, ringing phones."
  ],
  "accessibility": {
    "alt_text": "A finance lead reviewing a dashboard on a laptop, with neat stacks of paper beside them.",
    "contrast_target": "WCAG AA against the hero background."
  },
  "notes": "Brand voice is calm-expert. Avoid stressed body language, clutter, or red colours that read as alarm."
}
```

## When to pick which

| Situation                                                | Route                |
| -------------------------------------------------------- | -------------------- |
| Empty state, error, success, simple icon                 | A. Inline SVG        |
| Hero image, landing page art, blog header                | B. JSON image-prompt |
| Single-colour pictogram, navigation icon                 | A. Inline SVG        |
| Social media card, ad creative                           | B. JSON image-prompt |
| Onboarding illustration, in-app spot illustration        | A or B, depending on style and budget |
| Press kit photo, customer-story portrait                 | B. JSON image-prompt |

When in doubt, default to Route A. Inline SVG is cheaper to ship, easier to maintain, and works in dark mode without a second file.

## How to deliver the graphic

- For inline SVG, paste the SVG code in a fenced ` ```svg ` block, with two or three lines of placement notes above it (the parent token to use, the size, the alt text).
- For JSON image-prompt, paste the JSON in a fenced ` ```json ` block, with one line naming the target model or designer hand-off.
- Always include the alt text. Always confirm the palette against the DaisyUI theme tokens for both light and dark. Never embed text inside the image itself when the copy already states the message.

## Pairing with copy

The words and the picture are one unit. Get the copy from a writing brief or the `ux-copy` skill first, then build the visual to support it — not the other way around. A hero illustration is decoration without the headline; a state illustration is noise without the line that tells the user what to do next.
